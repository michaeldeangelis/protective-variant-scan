# V1: protective-variant scan

## Goal
Run the preregistered protective-variant scan (experiments.md, entry 2026-09-29 protective-variant-scan) end to end on public gene-based burden data and emit a verdict by the ledger's pass/kill rules.

## Done when
`python -m protscan run --config config/prereg.yaml --data data/ --out results/protective-scan.json` produces results/protective-scan.json and results/report.md containing: control status (positive, lambda_GC, permuted), rung counts (trivial/simplest/incumbent/candidate), Tier A-D gene lists, and a PASS / KILL / PROVISIONAL verdict. `pytest` passes. A reviewer (not the author) has checked conformance to the ledger.

## Stages (owner, state)
1. Normalized schema + config mirroring ledger thresholds (builder-pipeline, stub)
2. Source adapters -> normalized table: discovery, replication, constraint (builder-data, stub)
3. Stats: direction-of-benefit, discovery filter, replication, trade-off screen, tiering (builder-pipeline, stub)
4. Controls: synonymous lambda_GC, permutation null, positive controls PCSK9/ANGPTL4/APOC3 (builder-pipeline, stub)
5. Report + verdict logic (builder-pipeline, stub)
6. Ledger-conformance tests + review (reviewer, stub)
Lead: integration, experiments.md, this file.

## Interface (fixed)
Normalized long table, one row per gene x trait x mask x cohort: gene, trait, mask (plof|dmis|syn), cohort, beta, se, p, n_carriers, n_total, source. Direction of benefit (+1/-1 per trait) lives in config/prereg.yaml, not in the data.

## Decisions
- D1: Python 3.11+, pandas/numpy/scipy, pytest, no GPU. Why: summary-table statistics only. Flip: if tables exceed memory, switch to polars/duckdb.
- D2: Walking skeleton runs on synthetic tables with planted signals (a beneficial gene, an adverse-tradeoff gene, a null block) before any real download. Why: tests controls and tiering logic independent of data access.
- D3: Team = builder-data, builder-pipeline, reviewer; lead integrates. Why: two separable workstreams plus independent check on preregistered rules.
- D4: Thresholds are copied from the ledger into config/prereg.yaml; a test asserts they match. Changes only via a new dated ledger entry. Flip: never silently.
- D5: Repo is local only; no remote, no push until the user asks. data/ is gitignored; only code, docs, small results are tracked. Nothing here is sensitive; still review before any public push.
- D6: Analysis only. No content about modifying human genomes.

## Stop only for
- spending money or paid compute beyond the budget ($0 AWS)
- credentials, logins or access we cannot obtain (e.g. an application-gated dataset)
- irreversible or outward-facing actions (pushing to a public repo, publishing)
- the goal being impossible as stated
